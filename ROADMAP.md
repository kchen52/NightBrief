# NightBrief roadmap

Native Android go/no-go digest (`app.nightbrief`, `versionName` 0.1.0, `minSdk` 26, `compileSdk`/`targetSdk` 35). Kotlin + Compose, modules in `settings.gradle.kts`. Read `README.md` before changing score weights, the Bortle grids, or digest scheduling.

## Status

MVP is the on-device night score, a 7-night outlook, site book with GPS / osmdroid picker / manual entry, gear exposure hints, and a morning digest notification.

## P0 — verify the MVP on a device

- [ ] **Onboarding** (`app/src/main/kotlin/app/nightbrief/app/ui/onboarding/OnboardingScreen.kt`, four steps). Site step uses `SiteForm`: Use GPS (`LocationHelper`, fine + coarse), Pick on map (`MapPickerDialog` in a `Dialog` with `usePlatformDefaultWidth = false`), and typed lat/lon. After coordinates settle (~400 ms) Bortle fills from `AppGraph.bortleLookup` unless the user already set a class, and the IANA zone fills from Open-Meteo unless the zone was edited by hand. Failed zone lookup falls back to the device zone. Gear step starts as Canon EOS R7 + Sigma 10–18mm f/2.8 (`GearCatalog.exampleKit`). Finish writes the site, gear, and digest time.
- [ ] **Main screens** after onboarding (`NightBriefNavHost`): Tonight, Week, Sites, Gear, and Settings (Settings is pushed from Tonight, not a tab). Week row opens `PlannedNightScreen` at `night/{siteId}/{date}`.
- [ ] **Notifications and exact alarms.** On API 33+ the last onboarding step and Settings request `POST_NOTIFICATIONS`. On API 31+ Settings shows exact-alarm state and opens `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` when `canScheduleExactAlarms()` is false. With permission, `DigestScheduler` uses `setExactAndAllowWhileIdle`; without it, `setAndAllowWhileIdle`. Manifest permission is `SCHEDULE_EXACT_ALARM` (`work/src/main/AndroidManifest.xml`).
- [ ] **Send digest now** (Settings) enqueues an expedited `DigestWorker` for the primary site only (`AppViewModel.sendDigestNow`). Tapping the notification opens Tonight with that site selected (`DigestNotifier.EXTRA_SITE_ID` → `MainActivity`, `launchMode=singleTop`).
- [ ] **Reboot.** `RescheduleReceiver` re-arms on `BOOT_COMPLETED`, package replace, time/zone change, and exact-alarm permission change. `NightBriefApp.onCreate` also reschedules. Confirm the next alarm still exists after reboot. Primary uses the global time (default 08:00) unless it has an override; other sites fire only with an override (`DigestTimes`).
- [ ] **Offline morning.** `DigestWorker` always force-refreshes. If the fetch throws and the cache is under 48 h, the notification includes “Offline — showing the last saved forecast” (`DigestComposer`, `ForecastStatus.STALE`) and a network-constrained worker (15 min delay, 15 min exponential backoff, `setSilent`) replaces that notification in place (`DigestScheduler.scheduleRefresh`). In the app, the same banner is `NightDetail` and only appears for `STALE`. A cache younger than 60 min opened with `refresh(force = false)` is `CACHED` and shows no banner; use the Tonight refresh button offline to see it. `PrefetchWorker` runs every 3 h on a connected network.
- [ ] **`./gradlew assembleRelease` with R8.** `app/proguard-rules.pro` keeps kotlinx.serialization companions/serializers and `-dontwarn`s OkHttp platform providers. There are no osmdroid keep rules. Confirm the release APK still loads forecasts (OkHttp), decodes `AppState` / `Forecast` JSON, and opens the map.
- [x] **Screenshot or Compose UI tests** for onboarding, Tonight (score, stale banner, site strip), and the map dialog. `app/src/test/kotlin/app/nightbrief/app/ui/RoadmapUiTest.kt` (Robolectric + `createComposeRule`). The map test opens `MapPickerDialog` and checks the OpenStreetMap credit. Paparazzi goldens in `TonightScreenshotTest` cover a scored Tonight, the stale-forecast banner, and the Perseids and ISS cards. The Compose host activity comes from `ui-test-manifest` on the debug classpath, so `testReleaseUnitTest` is disabled and the release APK does not include it. Device coverage of the same flows, plus Settings toggles, the planner date step, and large-font TalkBack labels, is `ConnectedNightBriefTest` and `ConnectedAccessibilityTest` and waits for a connected device.

## Known gaps & tech debt

- **Onboarding drafts survive process death.** `AppViewModel` writes the site draft and gear kit into `SavedStateHandle` as JSON. The step index and digest time still use `rememberSaveable`. `OnboardingProcessDeathTest` removes the Sigma lens, restores a new view model from the saved map, and checks the coordinates and the empty lens list. The site editor still uses `SiteDraftSaver` in `SitesScreen.kt`.
- **One `AppViewModel` for every screen**, created in `MainActivity` and passed through `NightBriefNavHost`. `selectedSiteId` is memory-only, so process death returns Tonight/Week to the primary site unless the notification intent sets `EXTRA_SITE_ID`.
- **Briefing refresh is tied to sites and gear, not every setting.** `AppViewModel` init collects `onboardingComplete` + `sites` + `gear` and calls `refresh(force = false)`, which runs `BriefingService.brief` (default 7 nights, all sites). A rename, reorder, primary change, or exposure-only gear edit refetches forecasts. Digest time, digest enabled, and `alternativeThreshold` do not (the threshold is read live in `TonightScreen`).
- **Ephemeris is planning-grade.** `Bodies` is the Astronomical Almanac low-precision Sun (~0.01°) and Moon (~0.3° longitude). `AstroTime.daysSinceJ2000` uses UT (the ~70 s TT−UT / ΔT offset is ignored). `Ephemeris.position` applies J2000 RA/Dec with no precession/nutation. Refraction is only the rise/set constant `HORIZON_ALTITUDE = -0.833`; other altitudes are geometric. The Moon does get topocentric parallax (`Bodies.topocentricAltitude`).
- **7Timer covers ~72 h** (`SevenTimerClient`). Later hours have null seeing/transparency, so `NightScoreEngine` estimates them from humidity and 250 hPa wind and marks the factor estimated. Week copy states nights 4–7 are estimated (`WeekScreen`). Open-Meteo still supplies cloud, wind, humidity, and jet-stream wind (`forecast_days` default 8).
- **GEM is a lat/lon box, not a country polygon.** `WeatherModel.forLocation`: `gem_seamless` when latitude ≥ 41.6 and longitude is in −141.1..−52.5; otherwise `best_match`. That includes the northern US border and drops most of Alaska (west of −141.1).
- **Bortle grids are CC BY-NC 4.0** (Falchi et al. 2016, doi:10.5880/GFZ.1.4.2016.001). Non-commercial only, so a paid release cannot ship `data/src/main/assets/bortle_na.nblp.gzip` and `bortle_world.nblp.gzip`. Settings shows `LightPollutionAttribution.TEXT`. World grid is 0.05° (7200×3600); cells the atlas does not cover (south of about −60°, north of about 85°, both poles) are 0 and lookup as no data. North America is 1/120°. See `core-sites/src/main/kotlin/app/nightbrief/sites/Bortle.kt` and `README.md`.
- **Leaving the atlas keeps the previous class.** `SiteForm` writes a looked-up Bortle only when the grid returns non-null, so a MAP class can stick after a move into a 0-byte or out-of-bbox cell. The slider also displays `draft.bortle ?: 5`, so a null class looks like Bortle 5 before it is stored (`Site.effectiveBortle` is 5).
- **Bortle I/O.** `StreamingGridBortleLookup` opens the gzip asset, reads the 40-byte header, and skips to one byte on every call. Worst case on the North America grid is about a second. `AppViewModel.lookupBortle` uses `Dispatchers.IO`. Grids are not cached in memory on purpose.
- **Lint warnings are not gated.** No `lint.xml`, baseline, or `warningsAsErrors` in `app/build.gradle.kts`. `:app:lintDebug` can be green with warnings left over; the repo has no lint report. Suppressions in code: `@Suppress("MissingPermission")` in `DigestNotifier.post`, `@SuppressLint("MissingPermission")` in `LocationHelper`. `app/src/main/res/values/strings.xml` is only `app_name`; UI copy is hardcoded in composables.
- **Dependencies are pinned to late 2024** in `gradle/libs.versions.toml` (AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01, OkHttp 4.12.0, osmdroid 6.1.20, Work 2.10.0, DataStore 1.1.1). Wrapper is Gradle 8.11.1. README asks for JDK 21; module bytecode target is 17.
- **No CI.** No `.github` workflows. The live `DigestWorker` test needs network and will fail offline.
- **One alarm slot.** `DigestScheduler` uses a single `PendingIntent` (request code 1001). Multiple wall-clock times work only because `DigestAlarmReceiver` re-arms the next instant after it fires.
- **Notification id** is `1000 + (siteId.hashCode() and 0x0FFF)` (`DigestNotifier`). Two sites can collide.
- **Corrupt settings are replaced wholesale.** `SettingsRepository` uses `ReplaceFileCorruptionHandler { AppState() }` (onboarding incomplete, example gear, no sites). File is `filesDir/datastore/app_state.json`.
- **`DigestWorker` scores every site** (`outlookDays = 1`, `forceRefresh = true`) even when only the primary is due.

## v0.2 features

Gear-aware exposure suggestions are already shipped. `TargetAdvisor` calls `ExposureCalculator.bestFor` (NPF, 500-rule, ISO from Bortle and moonlight) and Tonight / the digest show `ExposureSuggestion.summary`. Do not rebuild that.

- [x] **Aurora alerts (NOAA SWPC Kp).** `SwpcKpClient` in `:core-weather` reads `https://services.swpc.noaa.gov/products/noaa-planetary-k-index-forecast.json`. The live product is an array of objects; the client also accepts the legacy array whose first row is headers (`time_tag`, `kp`, `observed`, `noaa_scale`) and whose later rows are strings. `BriefingService` fetches Kp once per briefing (a failure leaves aurora empty and does not fail the brief) and sets `Briefing.kp` plus `NightReport.aurora` for the dark window. `DigestComposer` adds one line — leading the notification when the chance is possible or likely — and `NightDetail` shows an Aurora card. Kp is not a `NightScoreEngine` factor. High latitude is geographic |latitude| ≥ 55°, not the GEM box; at that latitude Kp ≥ 4 upgrades the chance by one step. `DigestWorker` already renders `Digest` lines.
- [x] **Meteor showers.** `MeteorShowers` in `:core-astro` is a static annual table (peak month/day, ZHR, radiant RA/Dec, active window, including the Quadrantids year wrap). `MeteorAdvisor` (a sibling of `TargetAdvisor`) samples radiant altitude every 10 minutes, scales ZHR with a Gaussian in days from peak, and rates moonlight. The result is `NightReport.meteor`, not a row in `suggestions`, so the imaging "Try:" line stays a photographic target. Tonight shows a Meteors card and the digest adds one line when `worthWatching` (radiant ≥ 20° and expected ZHR ≥ 10). No network.
- [x] **ISS passes.** `Sgp4` in `:core-astro` is a Vallado port (WGS-72) checked against the published `tcppver` vectors (component error under 1e-8 km). `IssPasses.during` turns that state into topocentric passes. `CelestrakClient` reads the NORAD 25544 GP element; `CachingTleSource` keeps it for 12 hours and will serve a cache up to 7 days old if the fetch fails. `AppGraph` wires the cache into `BriefingService`. A failed fetch leaves `NightReport.issPasses` empty and does not fail the brief. Tonight and the digest list only passes whose peak is inside the dark window.
- [x] **Planning-mode date picker.** `PlannedNightScreen` steps backward and forward with the route date as the source of truth. The range is tonight through tonight + `OpenMeteoClient.DEFAULT_FORECAST_DAYS - 1` (8 days). `NightBriefNavHost` replaces the current night destination so the back stack does not grow by one entry per day. Dates past coverage still return ephemeris with `ForecastCoverage.NONE` and the “beyond the forecast horizon” banner; the control itself stops at the horizon.
- [x] **Big Night alerts.** After a successful prefetch, `PrefetchWorker` scores tonight from the cache (`forceRefresh = false`). A site at or above `Band.EXCELLENT.min` (85) posts on the `big_night` channel. `AppState.lastBigNightAlerts` dedupes by site id and local night date. Settings has a switch under the digest switch (`bigNightAlertsEnabled`, default on). Scoring or notification failures do not turn a saved prefetch into a retry. Incomplete onboarding returns before any fetch.

## v1.0

- [x] **Home-screen widget (Glance).** `NightBriefWidget` in `:app` reads `AppGraph` (forecast cache plus `BriefingService`) and shows the primary site’s score, band, and Milky Way window. `:work` cannot depend on `:app`, so `DigestWorker` and `PrefetchWorker` call `WidgetRefresh.request`, a same-app broadcast (`app.nightbrief.action.REFRESH_WIDGET`) that `NightBriefWidgetReceiver` turns into `updateAll`. `updatePeriodMillis` is 0.
- [x] **Wear OS glance (optional).** `:wear` is a separate watch app (`applicationId` `app.nightbrief`, `minSdk` 30) and depends on `:data`, not `:app` or `:work`, so the phone widget and digest alarms do not depend on it. `WearGlance` in `:core-score` turns the primary site's score into the number and the verdict (`Verdict`: Go at 70, Maybe at 50, otherwise No-go). It is not a `NightScoreEngine` input. The phone publishes that snapshot on the Wear data layer (`WearGlance.PATH`) from `WearPublisher` when `WidgetRefresh` finishes updating the home widget and when `NightBriefApp` starts. A Wear failure is swallowed and cannot skip the widget update. `NightBriefTileService` is the tile (`BIND_TILE_PROVIDER`) and shows the site, score, and verdict; `WearActivity` shows the same text in `WearGlanceScreen`. The tile prefers the phone's data item and otherwise reads the watch's own `AppGraph`. No complication. Tests: `WearGlanceTest`, Robolectric Compose `WearGlanceScreenTest` (Go, Maybe, No-go, setup), `NightBriefTileTest`, and `WearPublisherTest` (missing Play services does not throw). Paparazzi goldens in `WearScreenshotTest` (Galaxy Watch 4 Classic, Go / No-go / setup) are copied to `docs/screenshots/wear-go.png`, `wear-nogo.png`, and `wear-setup.png`.

## Proposed (product review, Oct 2026)

Not committed scope. Ordered by value for effort. Before anything here, finish P0: the app has never been installed on a device, and no shipped feature has been seen by a user.

### Decisions needed first

- **Business model vs. the Bortle licence.** The grids are CC BY-NC 4.0, so any paid tier, ads, or in-app purchase means the light-pollution data has to be replaced first. Light pollution is only 5 points of the score, but Bortle also gates `TargetAdvisor` (`maxBortle`) and sets ISO in `ExposureCalculator.suggestIso`. Decide free vs. paid before v1.0. If paid, evaluate a VIIRS-derived source with a commercial-compatible licence and rebuild with `tools/build_bortle_grid.py`.
- **How do we know the score is right?** The only checks are three engine fixtures. There is no signal from real nights. The session log below is the cheapest way to get one.

### Tier 1 — small, uses data we already fetch

- [x] **Dew and frost risk.** `DewRisk` in `:core-score` flags dark hours where temperature − dew point ≤ 2 °C, and calls that hour frost when temperature ≤ 0 °C. Hours outside the dark window are ignored, and a missing temperature or dew point is not flagged. `NightReport.dew` carries the first flagged hour and the coldest dark-hour temperature. Tonight and `DigestComposer` show "Dew likely from 23:40 — bring a heater" (or "Frost likely…") and "Dress for −4 °C". Neither line is a `NightScoreEngine` factor, so the score fixtures are unchanged. Tests: `DewRiskTest` and Robolectric `DewUiTest`.
- [ ] **Cloud layers.** `cloud_cover_low/mid/high` are fetched and never shown. Thin high cirrus at 40% is a very different night from 40% low stratus. Add a low/mid/high split to the Hour by hour `TimelineCard`, and a short reason ("high thin cloud") on Tonight when high cloud makes up most of the total. Do not change the cloud weight without new fixtures (see `README.md`).
- [ ] **Per-night confidence on Week.** Today a fixed footnote says nights 4–7 are estimated. Show an "est." marker on each `NightRow` from `NightScore.factors.any { it.estimated }` (or a coverage value on `OutlookNight`), so a planned trip on night 6 is not read as a firm Go.
- [ ] **Configurable Big Night threshold.** Fixed at `Band.EXCELLENT.min` (85). At a Bortle 6 home site 85 almost never happens, so the alert never fires. Add a slider next to the existing `alternativeThreshold` slider (range 70–95) and store it in `AppState`.
- [ ] **Red night-vision mode.** The app is used at the site, in the dark. A red-on-black colour scheme in `NightBriefTheme` (toggle in Settings plus a quick toggle on Tonight's app bar) protects dark adaptation. Theme only; no engine changes.
- [ ] **Units.** Wind is always km/h (`NightDetail` timeline copy). The GEM box and the screenshots target North America. Add metric/imperial (km/h vs. mph, °C vs. °F for the dew feature above), with the default taken from the locale.

### Tier 2 — differentiators

- [ ] **Session log and score feedback.** The morning after a Go or Maybe night, ask once (from the digest or Tonight) "Did you shoot? How was it?" with 1–5 stars and an optional note. Store it locally next to the night's `NightScore` factors. This gives users a shooting history and gives us the first real data for comparing the score with what happened. Later, add "your sites tend to beat the forecast by N" and use the data to tune the dew and cloud-layer weights. Local only; no backend.
- [ ] **Something to shoot on bright-Moon nights.** For about a week each month the Moon pushes most nights to Maybe or No-go, and `TargetAdvisor` has little to offer besides constellations. Add the Moon itself (lunar close-ups, with the phase and terminator angle) and "moonlit landscape" targets to `TargetCatalog`, chosen when illumination is above 0.5. This keeps users opening the app during the part of the month they otherwise skip.
- [ ] **Local horizon per site.** Target windows and the Milky Way window assume a flat horizon (10° to 35° minimum altitude). Real sites have trees, ridges, and buildings. Add an optional minimum altitude for each of 8 compass directions to `Site` (entered in the site form, or by sweeping the phone with the compass later). Apply it in `TargetAdvisor.evaluate` and the Milky Way window. "The core clears the treeline at 23:10" is information no forecast site gives.
- [ ] **Tracker and filter in the kit.** `GearKit` has only bodies and lenses, so every exposure is untracked and capped at 30 s. That makes `idealFocalMm = 200` for M31 or 300 for M42 hard to act on. Add an optional star tracker and filters (dual-band, light-pollution) to `GearKit`. With a tracker, suggest sub-exposure length and total integration time. With a dual-band filter, allow emission nebulae in brighter skies and under more Moon (relax `maxBortle` and `maxMoonIllumination` for `EMISSION_NEBULA`).
- [ ] **Find darker sky nearby.** `SiteComparison` only compares saved sites. Offer "Darker sky within 60 km": sample the Bortle grid in rings around the primary site, score the best few candidates against the forecast, and show the results on the osmdroid map with a "Save as site" button. This is the natural next step after "is tonight good?" and helps users who have only one saved site. The grid stays streamed, so limit the number of lookups and run them on `Dispatchers.IO`.
- [ ] **Share a night plan.** A shareable image card (score, best window, Milky Way window, top target, site name or a coarse location) for clubs and group chats. Low effort, and the main way new users would hear about the app.

### Tier 3 — larger bets

- [ ] **Sky events calendar.** Planets, conjunctions, eclipses, and comets. Needs planetary ephemeris in `:core-astro` (VSOP87 truncated, or bundled Chebyshev tables). It would add a year-ahead planning view to the 8-day forecast.
- [ ] **Second forecast model for confidence.** Fetch a second Open-Meteo model and show "models agree" or "models disagree" on cloud. This doubles forecast calls per site; worth doing only if the session log shows cloud misses are the main complaint.

### Debt that users would notice

- **Corrupt settings wipe every site** (`ReplaceFileCorruptionHandler { AppState() }`). Add export/import of sites and gear (JSON via the share sheet), and keep a last-known-good copy to restore from.
- **Notification id collision** between sites (`1000 + (hashCode and 0x0FFF)`). One site's digest can silently replace another's.
- **No localisation.** `strings.xml` has only `app_name`. Move UI copy into resources before any non-English market.
- **CI.** Add a workflow that runs the JVM, Robolectric, lint, and Paparazzi tasks, and skips the live-network `DigestWorkerTest`.

## Conventions for agents

- **Module boundaries.** `:core-astro`, `:core-weather`, `:core-sites`, `:core-gear` are pure JVM (no Android). `:core-score` depends on those four. `:data` → `:core-score`. `:work` → `:data`. `:app` → `:work` only, so the UI reaches the engines through `AppGraph`. Put new scoring, ephemeris, and forecast parsing in `core-*` with unit tests; keep Compose, WorkManager, and notifications in `:app` / `:work`.
- **Tests.** JDK 21 and `ANDROID_HOME`. JVM: `./gradlew :core-astro:test :core-weather:test :core-sites:test :core-gear:test :core-score:test`. Android: `./gradlew :data:testDebugUnitTest :work:testDebugUnitTest :wear:testDebugUnitTest`. Full check used for this MVP: `./gradlew assembleDebug :app:lintDebug test`. `DigestWorkerTest.onboardedSitePostsTonightDigest` hits the network.
- **Ephemeris references.** `core-astro/src/test/kotlin/app/nightbrief/astro/NightEphemerisTest.kt` is checked against Skyfield 1.55 + DE421 (tolerances 4 min, 6 min for lunar rise/set). There is no generator script in the repo. To refresh values, use a Python venv with `skyfield`, load `de421.bsp`, and update the expected instants in that test. `tools/requirements.txt` is only numpy and rasterio (Bortle grids), not Skyfield.
- **Bortle grids.** Rebuild with `tools/build_bortle_grid.py`. The source raster is not in the repo; download the 2015 World Atlas artificial-brightness GeoTIFF (mcd/m²) from [doi:10.5880/GFZ.1.4.2016.001](https://doi.org/10.5880/GFZ.1.4.2016.001) and pass it as `World_Atlas_2015.tif`. Commands, bbox, and `--aggregate mean` are in `README.md`. Gzip into `data/src/main/assets/*.nblp.gzip` (suffix `.gzip`, not `.gz`, or AGP’s asset merger unpacks them). Do not commit uncompressed `.nblp`. Run `.venv/bin/python tools/test_build_bortle_grid.py`.
- **Score fixtures that must keep passing** (`core-score/src/test/kotlin/app/nightbrief/score/NightScoreEngineTest.kt`): clear moonless night in 86..95 (≈90, Excellent, Go); overcast in 9..21 (≈15, Poor, No-go); full-moon clear night in 49..61 (≈55, Maybe). Bands: Excellent ≥ 85, Good ≥ 70, Fair ≥ 50, Marginal ≥ 30. Verdict: Go ≥ 70, Maybe ≥ 50.
- **Attribution to keep visible.** Open-Meteo CC BY 4.0; 7Timer; OSM “Map data © OpenStreetMap contributors” on the map (`MapPicker.kt`) and in Settings; `LightPollutionAttribution.TEXT` in Settings. The atlas is non-commercial only. Ephemeris credit in Settings points at the Astronomical Almanac low-precision formulas.
