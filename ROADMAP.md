## Known gaps & tech debt

- **Onboarding drafts survive process death.** `AppViewModel` writes the site draft and gear kit into `SavedStateHandle` as JSON. The step index and digest time still use `rememberSaveable`. `OnboardingProcessDeathTest` removes the Sigma lens, restores a new view model from the saved map, and checks the coordinates and the empty lens list. The site editor still uses `SiteDraftSaver` in `SitesScreen.kt`.
- **One `AppViewModel` for every screen**, created in `MainActivity` and passed through `NightBriefNavHost`. `selectedSiteId` is memory-only, so process death returns Tonight/Week to the primary site unless the notification intent sets `EXTRA_SITE_ID`.
- **Briefing refresh is tied to sites and gear, not every setting.** `AppViewModel` init collects `onboardingComplete` + `sites` + `gear` and calls `refresh(force = false)`, which runs `BriefingService.brief` (default 7 nights, all sites). A rename, reorder, primary change, or exposure-only gear edit refetches forecasts. Digest time, digest enabled, night vision, units, and `alternativeThreshold` do not (the threshold and units are read live in `TonightScreen`).
- **Ephemeris is planning-grade.** `Bodies` is the Astronomical Almanac low-precision Sun (~0.01°) and Moon (~0.3° longitude). `AstroTime.daysSinceJ2000` uses UT (the ~70 s TT−UT / ΔT offset is ignored). `Ephemeris.position` applies J2000 RA/Dec with no precession/nutation. Refraction is only the rise/set constant `HORIZON_ALTITUDE = -0.833`; other altitudes are geometric. The Moon does get topocentric parallax (`Bodies.topocentricAltitude`).
- **7Timer covers ~72 h** (`SevenTimerClient`). Later hours have null seeing/transparency, so `NightScoreEngine` estimates them from humidity and 250 hPa wind and marks the factor estimated. Week rows with any estimated factor show "est." (`OutlookNight.estimated`, `WeekScreen`). Open-Meteo still supplies cloud, wind, humidity, and jet-stream wind (`forecast_days` default 8).
- **GEM is a lat/lon box, not a country polygon.** `WeatherModel.forLocation`: `gem_seamless` when latitude ≥ 41.6 and longitude is in −141.1..−52.5; otherwise `best_match`. That includes the northern US border and drops most of Alaska (west of −141.1).
- **Bortle grids are CC BY-NC 4.0** (Falchi et al. 2016, doi:10.5880/GFZ.1.4.2016.001). Non-commercial only, so a paid release cannot ship `data/src/main/assets/bortle_na.nblp.gzip` and `bortle_world.nblp.gzip`. Settings shows `LightPollutionAttribution.TEXT`. World grid is 0.05° (7200×3600); cells the atlas does not cover (south of about −60°, north of about 85°, both poles) are 0 and lookup as no data. North America is 1/120°. See `core-sites/src/main/kotlin/app/nightbrief/sites/Bortle.kt` and `README.md`.
- **Leaving the atlas keeps the previous class.** `SiteForm` writes a looked-up Bortle only when the grid returns non-null, so a MAP class can stick after a move into a 0-byte or out-of-bbox cell. The slider also displays `draft.bortle ?: 5`, so a null class looks like Bortle 5 before it is stored (`Site.effectiveBortle` is 5).
- **Bortle I/O.** `StreamingGridBortleLookup` opens the gzip asset, reads the 40-byte header, and skips to one byte on every call. Worst case on the North America grid is about a second. `AppViewModel.lookupBortle` uses `Dispatchers.IO`. Grids are not cached in memory on purpose.
- **Lint warnings are not gated.** No `lint.xml`, baseline, or `warningsAsErrors` in `app/build.gradle.kts`. `:app:lintDebug` can be green with warnings left over; the repo has no lint report. Suppressions in code: `@Suppress("MissingPermission")` in `DigestNotifier.post`, `@SuppressLint("MissingPermission")` in `LocationHelper`. Phone UI copy is in `app/src/main/res/values/strings.xml`; notification copy is in `work/src/main/res/values/strings.xml`. Score, digest, and widget sentences that are built in `:core-score` stay there.
- **Dependencies are pinned to late 2024** in `gradle/libs.versions.toml` (AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01, OkHttp 4.12.0, osmdroid 6.1.20, Work 2.10.0, DataStore 1.1.1). Wrapper is Gradle 8.11.1. README asks for JDK 21; module bytecode target is 17.
- **CI** is `.github/workflows/ci.yml`. It runs `assembleDebug`, `lintDebug`, `test`, and `verifyPaparazziDebug` on JDK 21 with `NIGHTBRIEF_SKIP_LIVE_TESTS=1`, so `DigestWorkerTest.onboardedSitePostsTonightDigest` is skipped. That test still runs locally and calls Open-Meteo, 7Timer, and SWPC.
- **One alarm slot.** `DigestScheduler` uses a single `PendingIntent` (request code 1001). Multiple wall-clock times work only because `DigestAlarmReceiver` re-arms the next instant after it fires.
- **Notification ids are per-site slots.** `AppState.notificationSlots` assigns a positive int that is never reused, including after a site is deleted (`notificationSlotNext`). `DigestNotifier.digestNotificationId` is `10_000 + slot` and `bigNightNotificationId` is `30_000 + slot`, so two sites cannot replace each other's digest or Big Night notification. The old `hashCode and 0x0FFF` bucket is gone.
- **Corrupt settings restore the last good copy.** Every successful `SettingsRepository` read or update writes `filesDir/datastore/app_state.json.good`. `ReplaceFileCorruptionHandler` decodes that file and falls back to `AppState()` only when the backup is missing or unreadable. Settings can also export and import sites and gear as JSON (`LibraryTransfer`) through the share sheet and the system file picker. Digest time, notification slots, and alert history stay on the phone.
- **`DigestWorker` scores every site** (`outlookDays = 1`, `forceRefresh = true`) even when only the primary is due.

## v0.2 features

Gear-aware exposure suggestions are already shipped. `TargetAdvisor` calls `ExposureCalculator.bestFor` (NPF, 500-rule, ISO from Bortle and moonlight) and Tonight / the digest show `ExposureSuggestion.summary`. Do not rebuild that.

- [x] **Aurora alerts (NOAA SWPC Kp).** `SwpcKpClient` in `:core-weather` reads `https://services.swpc.noaa.gov/products/noaa-planetary-k-index-forecast.json`. The live product is an array of objects; the client also accepts the legacy array whose first row is headers (`time_tag`, `kp`, `observed`, `noaa_scale`) and whose later rows are strings. `BriefingService` fetches Kp once per briefing (a failure leaves aurora empty and does not fail the brief) and sets `Briefing.kp` plus `NightReport.aurora` for the dark window. `DigestComposer` adds one line — leading the notification when the chance is possible or likely — and `NightDetail` shows an Aurora card. Kp is not a `NightScoreEngine` factor. High latitude is geographic |latitude| ≥ 55°, not the GEM box; at that latitude Kp ≥ 4 upgrades the chance by one step. `DigestWorker` already renders `Digest` lines.
- [x] **Meteor showers.** `MeteorShowers` in `:core-astro` is a static annual table (peak month/day, ZHR, radiant RA/Dec, active window, including the Quadrantids year wrap). `MeteorAdvisor` (a sibling of `TargetAdvisor`) samples radiant altitude every 10 minutes, scales ZHR with a Gaussian in days from peak, and rates moonlight. The result is `NightReport.meteor`, not a row in `suggestions`, so the imaging "Try:" line stays a photographic target. Tonight shows a Meteors card and the digest adds one line when `worthWatching` (radiant ≥ 20° and expected ZHR ≥ 10). No network.
- [x] **ISS passes.** `Sgp4` in `:core-astro` is a Vallado port (WGS-72) checked against the published `tcppver` vectors (component error under 1e-8 km). `IssPasses.during` turns that state into topocentric passes. `CelestrakClient` reads the NORAD 25544 GP element; `CachingTleSource` keeps it for 12 hours and will serve a cache up to 7 days old if the fetch fails. `AppGraph` wires the cache into `BriefingService`. A failed fetch leaves `NightReport.issPasses` empty and does not fail the brief. Tonight and the digest list only passes whose peak is inside the dark window.
- [x] **Planning-mode date picker.** `PlannedNightScreen` steps backward and forward with the route date as the source of truth. The range is tonight through tonight + `OpenMeteoClient.DEFAULT_FORECAST_DAYS - 1` (8 days). `NightBriefNavHost` replaces the current night destination so the back stack does not grow by one entry per day. Dates past coverage still return ephemeris with `ForecastCoverage.NONE` and the “beyond the forecast horizon” banner; the control itself stops at the horizon.
- [x] **Big Night alerts.** After a successful prefetch, `PrefetchWorker` scores tonight from the cache (`forceRefresh = false`). A site at or above `AppState.bigNightThreshold` (default `Band.EXCELLENT.min`, 85) posts on the `big_night` channel. `AppState.lastBigNightAlerts` dedupes by site id and local night date. Settings has a switch under the digest switch (`bigNightAlertsEnabled`, default on). Scoring or notification failures do not turn a saved prefetch into a retry. Incomplete onboarding returns before any fetch.

## v1.0

- [x] **Home-screen widget (Glance).** `NightBriefWidget` in `:app` reads `AppGraph` (forecast cache plus `BriefingService`) and shows the primary site’s score, band, and Milky Way window. `:work` cannot depend on `:app`, so `DigestWorker` and `PrefetchWorker` call `WidgetRefresh.request`, a same-app broadcast (`app.nightbrief.action.REFRESH_WIDGET`) that `NightBriefWidgetReceiver` turns into `updateAll`. `updatePeriodMillis` is 0.
- [x] **Wear OS glance (optional).** `:wear` is a separate watch app (`applicationId` `app.nightbrief`, `minSdk` 30) and depends on `:data`, not `:app` or `:work`, so the phone widget and digest alarms do not depend on it. `WearGlance` in `:core-score` turns the primary site's score into the number and the verdict (`Verdict`: Go at 70, Maybe at 50, otherwise No-go). It is not a `NightScoreEngine` input. The phone publishes that snapshot on the Wear data layer (`WearGlance.PATH`) from `WearPublisher` when `WidgetRefresh` finishes updating the home widget and when `NightBriefApp` starts. A Wear failure is swallowed and cannot skip the widget update. `NightBriefTileService` is the tile (`BIND_TILE_PROVIDER`) and shows the site, score, and verdict; `WearActivity` shows the same text in `WearGlanceScreen`. The tile prefers the phone's data item and otherwise reads the watch's own `AppGraph`. No complication. Tests: `WearGlanceTest`, Robolectric Compose `WearGlanceScreenTest` (Go, Maybe, No-go, setup), `NightBriefTileTest`, and `WearPublisherTest` (missing Play services does not throw). Paparazzi goldens in `WearScreenshotTest` (Galaxy Watch 4 Classic, Go / No-go / setup) are copied to `docs/screenshots/wear-go.png`, `wear-nogo.png`, and `wear-setup.png`.

## Proposed (product review, Oct 2026)

Not committed scope. Ordered by value for effort. The P0 device checks (notifications, exact alarms, send digest now, reboot, the offline morning digest, and the release APK) passed on a SM-F731W on 2026-10-02.

### Decisions needed first

- **Business model vs. the Bortle licence.** The grids are CC BY-NC 4.0, so any paid tier, ads, or in-app purchase means the light-pollution data has to be replaced first. Light pollution is only 5 points of the score, but Bortle also gates `TargetAdvisor` (`maxBortle`) and sets ISO in `ExposureCalculator.suggestIso`. Decide free vs. paid before v1.0. If paid, evaluate a VIIRS-derived source with a commercial-compatible licence and rebuild with `tools/build_bortle_grid.py`.
- **How do we know the score is right?** The only checks are three engine fixtures. There is no signal from real nights. The session log below is the cheapest way to get one.

### Tier 1 — small, uses data we already fetch

- [x] **Dew and frost risk.** `Dew` in `:core-score` reads `temperatureC` and `dewPointC`. A dark hour (the same hours `NightScoreEngine` scores) is flagged when temperature − dew point ≤ 2 °C, and that hour is frost when temperature ≤ 0 °C. The line uses the first flagged hour ("Dew likely from 23:00 — bring a heater"); if a later flagged hour is freezing it names both times. The clock time is the forecast hour, not an interpolated minute. The overnight low is the coldest sunset-to-sunrise temperature, so twilight counts and a daytime hour does not ("Dress for −4 °C"). `NightDetail` shows a Dew, Frost, or Overnight card and `DigestComposer` adds the same lines after the aurora line. The collapsed notification still leads with the verdict, or with aurora when that chance is prominent. It is not a `NightScoreEngine` factor; the three score fixtures are unchanged.
- [x] **Cloud layers.** `CloudLayers` in `:core-score` reads `cloudLow`, `cloudMid`, and `cloudHigh`. The hour-by-hour `TimelineCard` shows those three rows beside total cloud. Dark hours (the same hours `NightScoreEngine` scores) produce "high thin cloud" when the high sum is more than half the total and greater than the low and mid sums. A 40% high deck is that reason; a 40% low deck is not; exactly half is not. Twilight hours stay on the timeline and do not set the reason. It is not a score factor, so the cloud weight and the three score fixtures are unchanged. Tests: `CloudLayersTest` and Robolectric `CloudLayersUiTest`.
- [x] **Per-night confidence on Week.** `OutlookNight.estimated` is `NightScore.factors.any { it.estimated }`. Each `NightRow` appends "est." The footnote (`week_footnote`) explains the marker instead of saying every night 4–7 is estimated.
- [x] **Configurable Big Night threshold.** `AppState.bigNightThreshold` defaults to 85. Settings has a 70–95 slider beside the alternative-site slider. `PrefetchWorker` passes it to `BigNightAlerts.select`, which clamps values outside that range.
- [x] **Red night-vision mode.** `NightBriefTheme(nightVision)` swaps in a red-on-black `NightPalette`. Score colours stay ordered (brighter red is a better night) and contain no green or blue. Settings has a switch, and Tonight's app bar has a quick toggle. `AppState.nightVision` defaults to off so an older settings file stays on the blue theme. Theme only; it is not a score factor. The README frame is `docs/screenshots/night-vision.png` (`ReadmeScreenshotTest.nightVision`).
- [x] **Units.** `UnitSystem` in `:core-score` formats wind and dew temperature for Tonight and the digest. Metric is km/h and °C; imperial is mph and °F. `AppState.units` is null until the user picks one, and null follows the locale (`UnitSystem.fromLocale`: Fahrenheit regions such as the US, metric everywhere else, including the UK). The 2 °C dew spread and the 0 °C frost line stay in Celsius. Wind colours on the timeline still use km/h. The score weights are unchanged.
- [x] **Saved briefing for the field.** The last successful forecast for each site stays in `FileForecastCache` with no age cutoff. A normal open still reuses a file younger than 60 minutes (`CACHED`) and does not label it. After that, `ForecastRepository` tries the network and replaces the file on success. A failed fetch serves the saved file as `ForecastStatus.STALE` at any age; the 48-hour cutoff is gone. `NightPlanner` recomputes ephemeris, targets, and meteors on device and joins them to the saved hours. Nights those hours still cover keep a score. Nights past the last hour stay beyond the forecast. Tonight, the opened night, and Week show "Offline — forecast saved Tue 18:40" (`SavedForecast`, site zone). The digest uses that sentence. The widget and the watch add "Saved Tue 18:40" so the score is not shown as fresh. Tests: `ForecastRepositoryTest`, `PlannerAndDigestTest`, `DewTest`.

### Tier 2 — differentiators

- [x] **Session log and score feedback (MVP).** `SessionEntry` in `:core-score` stores site, night date, score when a report was at hand, 1–5 stars, an optional note, and creation time (local only, no backend). `SessionPrompt` asks once per site night from Tonight in the 06:00–12:00 local window (`morningPromptDate` + `shouldAsk`, keyed `siteId/yyyy-MM-dd`). `AppState.sessions` and `dismissedSessionPrompts` have defaults so older files still decode. Tonight shows the prompt card and a 5-night history. Follow-up: gate on Go/Maybe once tonight scores are persisted, add the digest entry point, and surface "your sites beat the forecast by N" to tune dew/cloud weights.
- [x] **Something to shoot on bright-Moon nights.** `TargetCatalog` adds `moon-closeup` and `moonlit-landscape`, both offered only when `NightEphemeris.moonIllumination` is above 0.5. The close-up reason names the phase and the terminator angle (degrees east of celestial north, bright-limb angle plus 180°). The landscape reason names the phase. They are imaging suggestions, so the Try: line can lead with them. A short lens still lists the close-up; the existing exposure row says it does not reach. Kp, meteors, and the three score fixtures are unchanged.
- [x] **Local horizon per site.** `Site.horizon` is eight optional altitudes (N through NW). Unset means no extra obstruction, so an older settings file stays flat. The site form has a Local horizon switch; turning it on starts every sector at 0°. `TargetAdvisor` requires altitude at least the catalog minimum and the sector the target is in. The Milky Way window uses the same mask. When that delays the start by 10 minutes or more, Tonight, the digest, and the widget say "The core clears the treeline at 23:10". When the mask hides a core that would otherwise clear 10°, they say the Milky Way core stays behind the treeline. Sweeping the phone with the compass is still later.
- [x] **Tracker and filter in the kit.** `GearKit` holds an optional `tracker: StarTracker?` and `filters: List<GearFilter>` (both defaulted, so older files still decode). `ExposureCalculator` lifts the 30 s cap to 120 s on a tracker (NPF×4, `TRACKED_SHUTTERS`) and adds a stack plan (`stackCount`, `integrationMinutes`: 30 min widefield, 60 min tele ≥100 mm). `TargetAdvisor.effectiveMaxBortle/MaxMoon` relax `EMISSION_NEBULA` by +2 Bortle / +0.4 Moon with a dual-band filter (+1 Bortle with an LP filter) and names the filter in the reason when it kept the target. Gear screen has Tracker and Filters sections from `GearCatalog.trackers/filters`. The three score fixtures are unchanged.
- [x] **Find darker sky nearby.** `DarkSkyFinder` in `:core-score` samples the Bortle grid in rings (15/30/45/60 km × 8 bearings) around the primary site, keeps samples darker than the site's class, and scores at most five against the forecast for tonight. Each candidate is annotated with paved-road access from OpenStreetMap via Overpass (`OverpassRoadAccessClient` in `:core-weather`, 500 m radius; drive-up means a mapped car road with a paved surface, otherwise hike-in, failures stay unknown and never block scoring). Tonight shows a Darker sky card with the score, Bortle/distance/compass, a Drive-up/Hike-in badge, All/Drive-up/Hike-in chips that filter without refetching, Save as site, and a read-only osmdroid map dialog with the OpenStreetMap credit. Grid lookups run on `Dispatchers.IO` with no in-memory cache; one bad cell or candidate forecast skips that candidate only. Tests: `DarkSkyFinderTest`, `DarkSkyFinderRoadAccessTest`, `RoadAccessTest`, Robolectric `DarkerSkyUiTest`, and goldens in `DarkerSkyScreenshotTest` (`docs/screenshots/darker-sky.png`).
- [x] **Share a night plan.** `NightPlanCard` in `:core-score` is the picture's facts: score, best window (hidden on a no-go night unless that window still scores at least 50, same rule as Tonight's hero), Milky Way window, and the first imaging suggestion. The place is the site rounded to 0.1° (about 11 km); the pin is not on the image or the caption. A stale forecast adds the saved-at line so the score is not shown as fresh. Tonight and the planner share it from the app bar (`Share night plan`). The PNG uses the blue palette even when night vision is on. `shareNightPlan` writes the file on a background thread and no-ops if the file cannot be written or nothing can receive the intent.

### Tier 3 — larger bets

- [x] **Sky events calendar.** `Planets` in `:core-astro` computes Mercury–Neptune from the JPL Keplerian-elements table (Table 1, 1800–2050; geocentric RA/Dec within 0.5° of DE421, worst measured 0.08°, magnitudes sane with a Horizons-fit Mercury phase curve). `SkyEvents` scans the year ahead for oppositions, greatest elongations, planet–planet conjunctions under 3°, Moon–planet appulses under 3°, lunar eclipses, solar eclipses with distance-aware limits, equinoxes/solstices, and shower peaks with the Moon's phase. ### Debt that users would notice

- [x] **Corrupt settings used to wipe every site.** `SettingsRepository` keeps `app_state.json.good` and restores it when the datastore file will not decode. Settings → Sites and gear exports JSON through the share sheet and imports it from a picked file (`LibraryTransfer`). A file that is not a library object with `sites` and `gear` is rejected and leaves the phone's library alone.
- [x] **Notification id collision.** Slots in `AppState` replace `1000 + (hashCode and 0x0FFF)`. Digest and Big Night ids are in separate ranges, and a deleted site's slot is not given to the next site.
- [x] **UI copy is in string resources.** `app/src/main/res/values/strings.xml` holds the phone UI, and `work/src/main/res/values/strings.xml` holds notification and channel text. English is the only `values` locale so far. Sentences produced in `:core-score` (digest lines, widget score line, wear verdict) are still code.
- [x] **CI.** `.github/workflows/ci.yml` runs the JVM, Robolectric, lint, and Paparazzi tasks and skips the live-network digest test.
